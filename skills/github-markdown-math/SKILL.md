# github-markdown-math

## Mathjax特有の対策

- 複数の規則や数式を並べるときは`\begin{array}`や`\begin{gathered}`を使う．

## レンダリングエラーを起こす可能性がある記述，代替策

### mathブロックが無効になる文脈を避ける

- `<details>`による折りたたみは使わない．GitHubでは`<details>`の中の` ```math `ブロックが表示されない．
- ` ```math `ブロックをリスト項目の中に字下げして置かない．字下げした数式ブロックも表示されない．

### インライン数式でのMarkdown記号とのコンフリクトの防止

- 推論規則などの文字を含む数式は，`$$ ... $$`ではなく` ```math `のコードブロックに書き，本体は`\dfrac`で組む．`$$`の中身はGitHubのMarkdown処理を受け，`*`の組が強調に，`\{`・`\,`・`\;`・`\\`がエスケープとして解釈されて式が壊れる．
- インライン数式もMarkdown処理を受けるので，`*`は`\ast`，`\{ \}`は`\lbrace \rbrace`，`\,`は`\thinspace`，`\;`は`\thickspace`で書く．
- GitHubでは，インライン数式の開始の`$`の直前が空白か行頭でないと数式として表示されない．読点や全角括弧の直後でも`， $x$`や`（ $x$ ）`のように空白を入れる．textlintなどはこの空白を許容するように設定すること．文の途中の`，$\mathit{atom}$`のような箇所で空白を入れ忘れやすいので，書き終えたら`[，．（「]\$`を検索して確認する．
- インライン数式で`}`の直後に下付きの`_`を続けると（`$\mathcal{T}_{n}$`，`$\mathit{removenames}_\Gamma$`など），GitHubが`_`を強調の記号と解釈して数式が壊れる．`$\mathcal{T}\_{n}$`のように`\_`と書く．表示数式（` ```math `）ではこのエスケープは不要である．

### サポートされていない数式

- `\phantom`はGitHubで表示されない．複数行の式で字下げを揃えたいときは`\quad`で代用する．
- `\textbackslash`は` ```math `ブロックで認識されない．文法規則などでバックスラッシュを書くときは，数式記号の`\backslash`で代用する（`\texttt{}`の中には入れない）．
- 意味の翻訳などに使う二重の角括弧（`\llbracket \rrbracket`や`[\![ ]\!]`）はGitHubで表示されない．普通の角括弧は代入 $[x \mapsto v]$ と紛らわしいので，二重の縦線`\lVert T \rVert`で代用する．`\|`はインライン数式でMarkdownのエスケープとして`|`に変わるので使わない．

## プレーンテキストと数式を使い分けるべき場面

- Unicodeの上付き・下付き文字による数式ではなく，インライン数式を使う．
- コードブロック内でのASCIIアートによる疑似的な推論図は使わない．
